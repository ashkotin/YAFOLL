# Переход синтаксиса YAFOLL к ANTLR4

**Принцип.** При *дословном переносе* правило и его `rid` (второй аргумент `crt_prnt`) сохраняются посимвольно. Если такая запись недопустима для ANTLR4, мы **не исправляем её молча**: помечаем несовместимость. Отдельно от переноса идёт *адаптация для ANTLR4*; каждая адаптация фиксируется здесь с соответствием исходному правилу. `rid` — идентификатор узла, используемый Yp; метка альтернативы ANTLR4 (`#label`) — имя синтаксического контекста, **не замена `rid`**.

**Состояние файлов.** `SA_FOLsn_grammar_only.y` — раннее извлечение продукции Bison без действий, не основной материал для переноса EBNF. `SA_FOLsn_grammar_only.md` и `YAFOLL_syntax.g4` — **адаптация**, а не дословная транскрипция: исходный `rid="..."` сохранён без изменений в комментарии у каждой из 34 языковых альтернатив, а в конце стоит совместимая с ANTLR4 метка. Эти файлы пока не являются работающим парсером: лексер и стратегия обработки ошибок не перенесены.

## Реестр уже сделанных адаптаций

| Что менялось | Исходная запись → адаптированная | Влияние / обязательное соответствие |
|---|---|---|
| Дефисы в `rid` | `st-3→#st_3`, `Dcl-4→#Dcl_4`, `Id_list_b-1→#Id_list_b_1`, `st-11→#st_11`, `Dcl-5→#Dcl_5`, `st-6→#st_6` | Дефис не допускается в имени метки. Исходные строки `rid` с дефисом должны передаваться Yp **точно**, не восстанавливаться из метки. |
| Ведущий `#` в `rid` | `#types→#typesSeq`, `#trml→#trml`, `#Id_list_bch→#idListBchSeq`, `#Id_list→#idListSeq`, `#st→#st` | В ANTLR4 первый `#` — синтаксис метки, а не часть её имени. Например, в `#st` метка равна `st`, но исходный `rid` равен строке `"#st"`. Некоторые метки переименованы также во избежание совпадения с именем правила. |
| Повторяющийся `rid` | Четыре альтернативы `term` имеют исходный `"_trmRE"` → четыре разные метки `#trmRE_Ide`, `#trmRE_Number`, `#trmRE_String`, `#trmRE_Natural` | Уникальность меток введена для ANTLR4; **не утверждать**, что эти исходные `rid` уникальны. В узлах Yp все четыре сохраняют `"_trmRE"`. |
| Конфликт имени | `conds` (исходный `rid`) → `#condsNode` | `#conds` конфликтует с именем правила `conds`. `rid` остаётся `"conds"`. |
| Имена токенов | `l_p/r_p/l_cb/r_cb/e_m/q_m→L_P/R_P/L_CB/R_CB/E_M/Q_M`; `Id/Ide/Number/String/Natural→ID/IDE/NUMBER/STRING/NATURAL` | Изменены **имена в грамматике**, не смысл лексем. Соответствующий лексер ANTLR4 ещё не задан; Bison/Flex-словарь нельзя считать автоматически перенесённым. |
| Имена нетерминалов | `TermList→termList`, `Id_list_bch→idListBch`, `Id_list_b→idListB`, `Id_list→idList`, `Statements→statements`, `Statement→statement` | В ANTLR4 имена правил парсера начинаются со строчной буквы. Исходные имена в документации и узлах Yp не следует менять автоматически. |
| Пять повторных правил Bison | Авторские EBNF-комментарии `types:type+`, `TermList:term*`, `Id_list_bch:Id_list_b+`, `Id_list:Id*`, `Statements:Statement+` | Показано авторское EBNF, а не техническая развёртка Bison. Рекурсивные ветки исходника **не вызывают** `crt_prnt`; `rid` для каждой последовательности берётся из её базовой ветки. |
| Восстановление после ошибок | `Statement : e_m error e_m`, `Statement : error DOT` не включены в `statement` | Это Bison-механизм с особым токеном `error`, а не предложения языка. У этих веток нет `crt_prnt` и `rid`; правила ошибок ANTLR4 потребуют отдельного решения. |
| Режим парсера | `%glr-parser` исключён | ANTLR4 не наследует автоматически стратегию разбора и разрешение неоднозначностей GLR. Эквивалентность разбора и деревьев **не проверена**. |

**Обязательная проверка при продолжении:** для каждой сохраняемой альтернативы сверять пару `(ANTLR #label, исходный rid)` с `crt_prnt` в `archive/dev/SA_FOLsn.y`; обработчик дерева ANTLR должен создавать узел с исходной строкой `rid`. Отдельно тестировать форму дерева, вложенные `term`, границы повторения в пяти EBNF-правилах и неоднозначности. Нынешняя статическая сверка подтверждает 34 строки `rid` и 34 различные ANTLR-метки, но не поведение работающего парсера.
